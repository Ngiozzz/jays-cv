- **Supabase** (PostgreSQL) + **Prisma**: use the pooled connection for the app, the direct connection for migrations; develop against an online Supabase **dev** project (Docker/local Supabase optional, later). Free tier while building; **Pro (~$25/month) for the live site** (free projects pause when idle)
- **Logins: Google sign-in (OAuth) for staff**, decided by the developer. **Invite-only**: only emails Jay invited can get in; removing or pausing someone blocks them at once; roles **owner** / **writer** and permissions live in our database. Run it with **Better Auth** (recommended: Google provider + organization plugin for businesses, invites, roles), storing its tables in Supabase (alternative: Supabase Auth + Google). Google Cloud setup: consent screen (app name, logo, privacy policy link), client ID and secret, return addresses for localhost and the live domain, publish to production. Optional later: an email magic-link backup. Clients still have **no login** (private tracking link).
- **Files: Supabase Storage** private buckets with short-lived signed links only (replaces Cloudflare R2)
- **M-Pesa via Safaricom Daraja (NOT Paystack)**: STK Push prompt as the main way to pay; payments to Jay's Paybill reported automatically (order number as the account number); a client-typed M-Pesa code is checked against Safaricom's data; one code can't pay two orders. Build in the Daraja **sandbox** (test Paybill 174379) using a tunnel; live needs Jay's Paybill/Till and a Daraja "Go Live" approval. No card payments for now. **Jay already has Paybill 4027127**; today clients type their name as the account number. The prompt sets the order number automatically; manual payers are asked for the order number; name-typed payments are matched by phone + amount + name, or go to an owner-only "Unmatched payments" list; non-website payments show as "Other payments".
- **Claude API** through the developer's own key, **tokens counted per business**; a "pretend" mode until a key is added
- **WhatsApp links** first, email later
- **Multi-business from day one**: Jay CVS is the first business on the platform
- Also: **Zod** (validation), **Resend + React Email** (invites, password resets, order emails), **Vercel Cron** (re-check late M-Pesa payments, abandon unpaid after 24h, auto-complete after 5 days, reminders, CV deletion), **Sentry** (errors), **Vitest + Playwright** (tests), **GitHub** (private repo), **Cloudflare Tunnel** (Daraja sandbox callbacks to your computer)

## Code standards (no spaghetti)
The developer asked explicitly for clean, well-structured code. Follow these from the first file.

**Structure: one folder per business area, clear layers**
```
src/
  app/                    # Next.js routes only: pages, layouts, route handlers (thin)
    (public)/             # website, jobs board, order card, tracking page
    (admin)/admin/        # admin screens
    api/                  # webhooks & callbacks (M-Pesa, auth)
  modules/                # business logic, one folder per area
    orders/               #   orders.service.ts (rules) · orders.repo.ts (Prisma) · orders.schema.ts (Zod) · orders.test.ts
    jobs/  payments/  ai/  team/  content/  finance/  tenants/
  lib/                    # shared plumbing: db.ts, auth.ts, env.ts, storage.ts, email.ts, money.ts
  components/             # reusable UI pieces (no business rules inside)
  styles/                 # the preview's CSS, moved over
prisma/schema.prisma      # the single source of truth for the database
```
- **Layers:** page/route → *service* (business rules) → *repository* (Prisma). Components never call Prisma; routes stay thin.
- **The order rules from `js/orders-core.js` become `modules/orders/orders.service.ts`** with unit tests (accept, reassign, send draft, revisions, auto-complete, abandon).
- **Every query is scoped to the business (tenant).** A helper enforces it, so one business can never see another's data.
- **Roles are checked on the server** (owner/writer permissions), never only by hiding buttons.

**Rules**
- **TypeScript strict mode**; no `any`. **Zod** validates every input (forms, API, M-Pesa callbacks) and the environment variables (`lib/env.ts` fails fast if a key is missing).
- **ESLint + Prettier**, run before every commit; no unused code, no commented-out code.
- **Small files, small functions, clear names.** One job per function. No copy-paste: shared logic goes in a module.
- **Money as whole shillings (integers)**, never floating point.
- **External services behind one interface each** (`payments/mpesa`, `ai/claude`, `lib/storage`, `lib/email`) with a **mock** version, so the app runs fully without keys and each service can be swapped.
- **Secrets only in `.env.local`** (never in code, never committed); `.env.example` lists every variable.
- **Tests:** Vitest for the rules (orders, payments, permissions, tokens); Playwright for the key journeys (order → pay → accept → draft → approve).
- **Git:** one small, working step per commit with a clear message; `main` always runs.
- **Comments explain *why*, not *what*.** A short README per module.

## Key rules to keep
- **Job seekers only**: no employer features.
- **Writers accept orders**: the first to accept gets it, recorded with who and when. Only Jay can reassign.
- **Paid but not accepted = red**, with ⚠ and a label.
- **Only Jay sees money**: prices, takings, fees, writer pay. Jay sees AI as a **token balance only** (1,000,000 starter tokens), never as money.
- **Writers work only on orders they accepted.** Client contact details, files, tracking link and AI are hidden on other writers' orders.
- **Jay controls everything**: Team (invite, permissions, pay %, pause, remove), Finance, Website content.
- **No client accounts at launch**: clients use a private tracking link.
- **Client CVs are personal data**: private storage, retention setting, never public viewers or free AI tiers.
